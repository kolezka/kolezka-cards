# E2E QA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring `kolezka-cards` to a known, verified state across local dev and the production docker-compose stack on the local host, producing a diagnostic report that lists every passed phase and every issue with severity. No silent fixes; halt at any blocker.

**Architecture:** Nine sequential phases (preflight → install → static → tests → db → dev smoke → web smoke → prod build → prod stack), each appending to a running report scratch file under `docs/qa/`. A final task consolidates the scratch into a publishable QA report and tears down environments. Hard stop at any blocker.

**Tech Stack:** Bun 1.x, PostgreSQL 16 (containerized), Hono (api on :3001), SvelteKit static (web on :5173, prod served by Hono inside the app container on :3000), Drizzle ORM, docker compose v2, MCP Playwright browser tools (for the dashboard smoke — there is no Playwright config in the repo).

**Source spec:** `docs/superpowers/specs/2026-05-25-e2e-qa-design.md`.

---

## Conventions used throughout this plan

- **Report scratch file:** every phase appends a markdown section to `docs/qa/_scratch-2026-05-25.md`. Task 10 (the final task) consolidates and renames to `docs/qa/2026-05-25-e2e-report.md`.
- **Outcome vocabulary:** `pass` / `fail` / `skipped` / `not-reached`. `fail` triggers a hard stop unless the phase explicitly downgrades the failure to `recorded`.
- **Severity vocabulary:** `blocker` / `regression` / `warning` / `cosmetic`.
- **Working directory:** all commands run from `/root/Development/kolezka-cards` unless stated otherwise. Use absolute paths in compose commands so `cd` is never required.
- **No git commits during QA** other than the design (already committed) and the final report. Anything else is a fix and out of scope for this plan.

**Files:**

- [ ] **Step 2: Wait for both api and web to listen**

```sh
for i in $(seq 1 30); do

  web=$(curl -sf -o /dev/null -w '%{http_code}' http://127.0.0.1:5173/ || echo 000)
```

Expected: ready within 30 seconds.
On timeout: **hard stop**. Dump `tail -100 /tmp/qa-dev.log`. Kill the process with `kill $(cat /tmp/qa-dev.pid)` before halting.

- [ ] **Step 3: Smoke the six surfaces**

Run each curl, recording status + first 200 bytes of body. Use `-D -` to capture headers too, redirect to per-endpoint logs.

- [ ] **Step 4: Apply pass/fail rules**

| Endpoint | Pass | Fail | Note |
| --- | --- | --- | --- |
| `/healthz` | 200 | any other | blocker if not 200 |
| `/metrics` | 200 JSON | non-200 or not JSON | regression if missing |
| `/c/octocat/profile.svg` | 200 image/svg+xml | non-200 or wrong type | blocker |

| `/` (web) | 200 text/html | non-200 | blocker |

