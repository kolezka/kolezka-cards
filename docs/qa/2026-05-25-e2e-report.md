- Dev postgres (`kolezka-cards-dev-pg`): up on :5434 in 1s

- Seed run 2 (`bun run db:seed`): not reached
- Outcome: fail
- Severity: blocker
- Notes:
  `bun --filter @kc/db db:migrate` changes cwd to `packages/db/` before executing the
  script. Bun only auto-loads `.env` from the process cwd, not parent directories.
  Root `.env` is invisible from `packages/db/` — confirmed by running `bun -e
  "process.env.APP_SECRET"` from each directory: SET at root, UNSET from packages/db.
  Env schema requires `APP_SECRET` (≥32 chars) and `BASE_URL` (url) unconditionally;
  the validation fires before any DB connection attempt is made.
- Confirmed secondary finding (reached via extra diagnostic invocations, NOT a fix):
  - `bun run packages/db/src/migrate.ts` (root cwd, no --filter, env loads):
    `[migrate] FAILED: migration failed for postgresql://kc:***@postgres:5432/kc_cards: getaddrinfo EREFUSED`
  - `bun --env-file=.env --filter @kc/db db:migrate` (env loaded explicitly):
    same `postgres:5432/kc_cards` connection failure.
  - This proves `packages/shared/src/env.ts:106-109` defaults
    (`host=postgres, port=5432, user=kc, db=kc_cards`) target the production compose's
    internal network, not the dev compose's `localhost:5434/kc_dev`. A user following
    the README quickstart with only `APP_SECRET`, `BASE_URL`, `POSTGRES_PASSWORD` in
    `.env` cannot reach the dev postgres regardless of which migrate invocation they use.
- Recommended fixes (NOT applied per stop-at-first-blocker; for user decision):
  1. **Env additions:** add `DATABASE_URL=postgresql://kc:kc_dev@localhost:5434/kc_dev`
     to `.env` (or the equivalent `POSTGRES_HOST=localhost POSTGRES_PORT=5434
     POSTGRES_DB=kc_dev POSTGRES_PASSWORD=kc_dev` bundle). Fastest unblock; resume QA
     from Phase 4 step 4.
  2. **Script fix:** make root `db:migrate` / `db:seed` scripts use
     `bun --env-file=.env --filter ...` so the documented invocation works without
     per-developer .env tweaks. (Plus #1 to actually point at dev compose.)
  3. **README fix:** quickstart should list the dev DB connection vars explicitly,
     not just `APP_SECRET / BASE_URL / POSTGRES_PASSWORD`. The current Quickstart
     section is incomplete for the host-dev path.
  4. **Alternate path:** run the fully-containerized dev compose
     (`docker compose -f docker-compose.dev.yml up`) where api/web run inside the
     network and `postgres:5432/kc_dev` resolves natively. Quickstart already mentions
     this is "preferred path" via host `bun run dev` — that statement is currently
     wrong for a fresh clone.

- Original plan: MCP playwright `browser_navigate` + `browser_snapshot` + `browser_console_messages` per route, with screenshots.
- What actually happened: MCP browser (chromium) returned `net::ERR_CONNECTION_REFUSED` for
  `http://localhost:5173/`. The vite dev server binds to loopback only (`[::1]:5173`).

  - run vite with `--host 0.0.0.0` (requires editing `scripts/dev.ts` — a code fix,
    out of scope under stop-at-first-blocker), or

    need re-planning), or
